## 引入格莱斯四条准则作为说话方式（说明书 v1.0 → v1.1）

用户提出「把严格遵守格莱斯合作原则加进我们的沟通」。用户未回答我给的选项，按其 skip 指示自行决策落地。

**落点：重写 `02_AI_prompts_指令库/00_给AI的说明书.md` 第八节**，不新建触发词文件——理由是说话方式属常驻规则，而触发词是"启动一个流程"，两者性质不同。

**四条准则落到实际行为：**
- 数量：答完就停，禁止结尾追加"顺便说一句/另外提醒一下"；铁律五的清单不算违反
- 质量：不确定就说不确定，禁用"一般来说/通常/大概率"兜底
- 关系：只答被问的，不扩展成"你还可以考虑……"
- 方式：结论放第一句、术语只解释一次、分点最多两层

**关键设计判断（这是我这次真正的取舍）：**
严格按关系准则会砍掉我过去最有价值的输出——那些"顺带发现"（002 与 001 两套规则打架、05 文件夹建库时漏说明、入门指南里内嵌会过期的口令副本）全部发生在用户问题之外。
所以设「踩坑提醒」豁免，但只给四类：**花钱 / 伤身体 / 数据不可逆 / 返工**，最多两句，其余一律不提。设白名单而非黑名单，是因为黑名单永远堵不完，最后又会回到啰嗦。

**新增两个开关：** `严格：` 切严格档（豁免取消，持续到本次对话结束），`恢复` 退出。依据是用户原话"当我需要"，说明他要的是可调档位而非一刀切。

**同步改动：**
- 说明书 §〇 触发表加 `严格：`、`恢复` 两行；版本号 1.0 → 1.1
- `MEMORY.md` 新增「说话方式」节 + 触发表两行（改此文件时曾误删「知识库触发词」小节标题，已修复）
- `00_使用手册.html` 05 速查：标题"七个词"改为"这几句话"（避免数量写死），新增 `严格：` 卡片 + 一段格莱斯说明

**没做的事：** 没给格莱斯原则单独建口令文件。三条规则塞一个文件属于过度工程，直接指向说明书 §八 即可——反正说明书是每次对话第一步必读的。
